# Sanity check of the extraction — 28 Jul 2026

Ran before building the MILP, on the theory that a solver fed bad data produces
confident nonsense. Two real bugs found, one of them serious. Everything checked
is listed below, including the checks that passed, so this doubles as a record of
what has and hasn't been verified.

## Verdict

The structural extraction is sound. The *stat* extraction had a hole that would
have silently broken the planner's recommendations for the most important stars
in the game.

**Status: both bugs fixed.** `scripts/extract.mjs` was rewritten to follow nested
records and resolve display tags. See "After the fix" at the bottom for the new
numbers and the two caveats that came out of it. The bug write-ups below are kept
as the record of what was wrong and why.

---

## Bug 1 (serious, FIXED) — stats hidden one DBR level down are never read

`extract.mjs` reads each star's skill DBR and stops there. But 31 of 559 stars are
shells that point at another record where the real stats live:

- 11 stars via `buffSkillName`
- 20 stars via `skillProjectileName`

For the 11 `buffSkillName` stars the parent record is nearly empty, so they
currently extract as **zero or one stat, `maxLevel` 1, `cooldown` 0**:

| Star | extracted stats | real stats one level down |
|---|---|---|
| Dying God #7 (Hungering Void) | 1 (`instantCast`) | 15 |
| Murmur #4 | 0 | 16 |
| Samael's Witchblade #5 | 0 | 16 |
| Assassin's Blade #5 (Assassin's Mark) | 0 | 8 |
| Rattosh #6 | 0 | 9 |
| Huntress #7 | 0 | 11 |
| Wendigo #6 | 0 | 8 |
| Dire Bear #6 | 1 (`pointBlank`) | 11 |
| Menhir's Obelisk #7 | 1 (`instantCast`) | 11 |
| Tree of Life #6 | 1 (`instantCast`) | 12 |
| Harp #6 | 1 (`instantCast`) | 12 |

These are not obscure stars. Hungering Void and Assassin's Mark are two of the
most-taken devotion procs in the game. As the data stands, the objective function
scores them at roughly zero and the planner would never recommend them.

What's actually in Hungering Void's buff record, for comparison:

```
offensiveChaosModifier        [15 levels]  70 -> 370
offensiveLifeModifier         [15 levels]  70 -> 370
offensiveSlowLifeModifier     [15 levels]  70 -> 370
retaliationChaosMin           [15 levels]  90 -> 720
offensiveCritDamageModifier   [15 levels]   8 -> 18
characterTotalSpeedModifier   [15 levels]   3 -> 10
retaliationFearChance         [15 levels]  25 -> 70
skillCooldownTime             30
skillActiveDuration           20
```

Note also that `skillExperienceLevels` lives in the buff record too — so the
"`skillMaxLevel` lies, use `skillExperienceLevels.length`" workaround silently
fails for exactly these 11 stars, which is why they all report `maxLevel: 1`.

**Fix required** before the MILP: follow `buffSkillName` and `skillProjectileName`
one level and merge (see open question below).

## Bug 2 (cosmetic but user-visible, FIXED) — `FileDescription` is a dev name, not a display name

27 of 109 constellations have a `FileDescription` that differs from the name the
game shows. Some are cosmetic, several are simply wrong:

```
Eye of Dreeg          -> Eye of the Guardian
Sandclaw              -> Nighttalon
Caller of The Frost   -> Amatok the Spirit of Winter
Pestilence            -> Affliction
Samael's Witchblade   -> Solael's Witchblade
Beetle                -> Scarab
Turtle                -> Tortoise
Candle                -> Scholar's Light
Harp                  -> Bard's Harp
Menhir's Obelisk      -> Obelisk of Menhir
StaffRattosh          -> Staff of Rattosh
AlladrahPhoenix       -> Alladrah's Phoenix
AttakSeru             -> Attak Seru, the Mirage
...and 14 more
```

**Fix:** use `constellationDisplayTag` resolved against `text_en`. Verified that
all 109 tags resolve, and 548 of 559 star `skillDisplayName` tags resolve. The
11 that don't are precisely the `buffSkillName` stars from Bug 1 — their display
tag is in the buff record, so fixing Bug 1 fixes this too.

## Checks that passed

**Completeness.** 109 constellation records = 104 real + 5 Crossroads. The wiki
gives 105 (counting Crossroads once), so nothing is missing. Star counts per
constellation are 3–8, matching the wiki exactly. IDs run 1–110 with only
`constellation87` absent, which is an unused slot rather than a parse failure.

**Affinity graph.** 5 affinities (eldritch, chaos, ascendant, primordial, order).
Highest single requirement is 20; total obtainable if you took everything is
46–90 per affinity, so requirements are satisfiable and the constraint is
non-trivial — good, that means the MILP is doing real work.

**Prerequisite structure.** `devotionLinks` keys run 2–8, each holding exactly one
integer parent, and star 1 never has one. So the intra-constellation graph is a
single-parent tree, never a DAG with joins. The current `prereq` parse is correct.
Confirmed branching exists (Korvaak: stars 4, 5, 6 all depend on 3), so the
scheduler can't assume a straight chain.

**Ragged arrays.** Only 4 stars have per-level arrays of differing lengths, and
there are currently **0** stars where `maxLevel` exceeds the longest array — so
the NaN risk noted last session is real in principle but not currently triggered.
Clamp anyway; fixing Bug 1 will add new arrays.

**Scheduler.** `src/lib/schedule.mjs` — 6/6 tests pass.

## Label coverage — corrected, and lower than last session's estimate

Last session estimated "~185 of 225 covered". That was optimistic. Actual numbers,
after porting `EnglishLanguage.cs` (775 entries) and reconciling:

| | count |
|---|---|
| Raw distinct stat fields | 270 |
| — technical/internal (fx, geometry, weapon-type flags) | 66 |
| — direct string present in `labels.json` | 72 |
| — covered only via StatManager's generic damage templates | 66 |
| — no coverage | 66 |

Grouped into families (Min/Max/Chance/Duration merged): **88 of 130 covered,
42 need hand-written labels.**

The important caveat: the 66 "template" fields are *not* ready to use. iagd
doesn't store a string for `offensiveFireModifier`; it composes one at runtime
from `customtag_damage_13%` plus a damage-type name. Porting the dictionary alone
doesn't get those — the composition logic has to be reimplemented. So the honest
count of fields with a usable string today is 72, not 138.

The 42 uncovered families cluster into three predictable groups: attribute
requirement reductions (`characterMeleeStrengthReqReduction` etc.), DoT/debuff
durations (`defensiveFireDuration`, `offensiveSlowRunSpeed`), and crowd control
(`offensiveFreeze`, `offensivePetrify`, `offensiveKnockdown`, `offensiveConfusion`).
Full list in `label-review.json`.

# After the fix

Nested was chosen. Child stats attach as `star.grants`, never merged into
`star.stats`, so the objective can always tell "+X passively" from "grants a proc
that does Y" — which §7.5's `chance / recharge` scoring needs.

## New schema

```js
star = {
  index, ref, displayTag,
  name,            // resolved from text_en, never FileDescription
  prereq,          // single parent index, or null for star 1
  maxLevel,        // max(own XP table, granted XP table, 1)
  cooldown,        // own skillCooldownTime, falling back to the grant's
  stats: {},       // passive stats on the star itself
  grants: null | { kind: 'buff' | 'projectile' | 'pet',
                   ref, name, displayTag, maxLevel, cooldown, duration,
                   stats: {},        // empty for pets, on purpose
                   petOwnStats: {} },// pets only; quarantined, see below
  proc:   null | { raw, trigger, chance },
}
```

## Numbers after the fix

| | before | after |
|---|---|---|
| Distinct stat fields | 270 | 311 |
| Stars with zero stats | 6 | **0** |
| Stars with unresolved display name | 11 | **0** |
| Stars with `maxLevel` > 1 | 52 | **63** |
| Stars with a proc trigger | 52 | **63** |
| Field families covered by a label | 88/130 | 91/138 |

The strongest signal that this is now right: **63 stars have `maxLevel` > 1 and
exactly those same 63 have a proc trigger.** Celestial powers are precisely the
levelled, proc'd stars, and the two independently-derived sets agree perfectly.
Before the fix both counts were 52 and the sets did *not* line up.

Spot checks:

- **Hungering Void** — was `maxLevel` 1, cooldown 0, 1 stat. Now `maxLevel` 15,
  cooldown 30s, 15 stats (`offensiveChaosModifier` 70→370 across levels).
- **Assassin's Mark** — was `maxLevel` 1, 0 stats. Now `maxLevel` 25, 8 stats
  including the resistance shred (`defensivePhysical` −4→−32, `defensivePierce`
  −8→−36) that makes it meta-defining.

## Two things that came out of the fix

**1. Pet stats are quarantined.** `spawnObjects` turned out to point at `Pet` /
`PetPlayerScaling` *creature* templates — ~800 fields of animation speeds, equip
chances and sound weights, which is why the naive fix ballooned the field count to
1110. Worse, their `defensive*` values are the **pet's own** resistances. Merging
them would make a "fire resistance" search surface Revenant because the skeleton
resists fire. So for `kind: 'pet'`, `stats` is deliberately empty and the pet's
own numbers sit in `petOwnStats`, which the objective must ignore unless it is
explicitly scoring a pet build. The star's genuinely player-facing fields
(`petLimit`, `petBurstSpawn`) are unaffected — they live on the star itself.

**2. `chance / recharge` divides by zero for 14 procs.** Assassin's Mark, Wendigo's
Mark, Turtle Shell, Ghoulish Hunger and 10 others report `skillCooldownTime` 0 in
both the parent and the child. They're not actually uncapped in game; GD gates them
some other way (buff duration, internal lockout) that isn't in the DBR. §7.5 needs
an explicit rule for these rather than an unguarded division.

## Labels, after re-reconciling against the now-larger field set

`labels.json` is now generated as **775 ported from iagd + 3 hand-written = 778**.
Hand-written entries live in `labels.extra.json` and are merged over the port by
`port-labels.mjs`; `labels.json` itself is regenerated and should never be edited.
The 3 seeded entries are proc triggers iagd lacks (`cast_@selfat45%health` and
friends) — found because every proc trigger is now checked against the label table.

**91 of 138 families covered; 47 still need hand-written labels** (up from 42
because following the nested records surfaced new fields such as `contagion*` and
`retaliationFear`). Full list in `label-review.json`. They cluster into four groups:
attribute requirement reductions, DoT/debuff durations, crowd control
(freeze/petrify/knockdown/confusion), and the Pestilence contagion mechanic.

## Still true after the fix

Scheduler still passes 6/6 — it reads `constellations[id].name`, which survived the
rename (`FileDescription` moved to `devName`; `name` is now the resolved display
name). Constellation count, affinity graph, prereq tree and ragged-array clamping
are unchanged and were verified above.
